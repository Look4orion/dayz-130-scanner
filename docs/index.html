DayZ 1.30 Mod Scanner

Checks a mod's scripts for the known DayZ 1.30 breaking changes, and whether the same build still compiles on 1.29.

Your files never leave your computer. The scan runs in this browser tab and nothing is uploaded: the page can't send data anywhere except a visit counter (GoatCounter, no cookies), which records only that the page was opened or a scan was run, never anything about your files. Once loaded, the scanner works offline.

Drop mod folders or .pbo files here

A mod folder is the one with an Addons folder inside (@MyMod, or a Workshop number folder). You can drop several mods, or a whole folder of mods, at once.

Reading the results

break Breaks on 1.30
Code 1.30 will not compile or will silently skip: overrides of methods that were removed or changed, name clashes with methods vanilla added, script folders written with backslashes (1.30 loads none of their scripts, with no error), modded class GameConstants, #include "$profile...".
risk Check by hand
Uses something 1.30 removed or changed, where the scanner can't tell for sure from the name alone: folder listings with FindFile (they return nothing for $profile: folders on 1.30), menus taking global input focus with ChangeGameFocus, methods 1.30 made protected, version gates like #ifdef DAYZ_1_30 that switch off again on 1.31.
info Good to know
Still works, but behaves differently on 1.30: CreateInInventory refusing items that don't fit, obsolete methods, car headlight overrides 1.30 no longer calls.
1.29 Won't compile on 1.29
For builds that must still run on 1.29 servers: code that uses classes or methods that only exist from 1.30, outside a #ifndef DAYZ_1_29 block.

What it can't tell you

  • A clean result means no known breaker was found, not that the mod works. It reads code; it doesn't run it.
  • It matches by name. A mod's own field or class that happens to share a name with something vanilla removed shows up as a "check by hand" hit. Read each hit before reporting it to an author.
  • Config is not checked (for example, 1.30 needing a _Ruined class for every car wheel).
  • Code under a mod's own #ifdef is checked both ways, as if the define could be on or off.
  • Mods that reference each other: drop them together, so names one mod defines count as known for the others.

Compares against an index of vanilla class and method names built from the game's own scripts (DayZ 1.29.163709 and 1.30.164014). The same scanner also runs from the command line: source and instructions.
